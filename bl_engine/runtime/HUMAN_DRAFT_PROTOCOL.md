# HUMAN DRAFT PROTOCOL — 말로 쏟고, 빼기만 한다 (목소리 층 v6)

이 문서는 BL 원고·블로그·에세이 모두에 적용한다. 다른 런타임 문서와 부딪치면 **쓰는 순서는 이 문서가 이긴다.** 문체 규칙(VOICE_BIBLE, BL_LAYER)은 그대로 둔다.

## 왜 바꾸나

v5까지 엔진은 '사람 같은 장치를 더하고, 걸린 문장을 더 잘 고치는' 방식이었다. 그 결과 블로그 1일차 초안은 검사기 0점·판별기 0.986으로 통과했는데, 사용자는 읽자마자 "AI가 잘 쓴 느낌, 잘 쓰려고 노력한 느낌"이라고 잡았다. 뜯어보니 원인은 단어가 아니라 **퇴고 때 더해진 설계**였다.

| 더해진 설계 | 그 초안의 예 | 원작 BL 덩어리에서 나오는 비율 |
|---|---|---|
| 교훈 문장 (S07) | 남이 안 보는 글은 쓰는 사람한테도 조금씩 거짓말을 시킨다. | 0.2% |
| 회수 요약 (S08) | 다 쓰고 보니 결국 같은 니트 얘기였다. | 0.2% |
| 거울 구조 (S09) | 낭만 문단의 니트·옷깃·은행잎 소리를 쓸쓸함 문단이 하나씩 되받음(공유 소재 15개) | 공유 소재 p99 = 9개 |
| 문단마다 한 줄 펀치 | 그게 나다. / 웃기는데 좋다. / 노렸다면 좀 분하다. | — |
| 검색어 끼워 넣기 (B02) | 가을 감성 글귀를 검색하면 하늘이 높고… | — |
| 계절 소품 세트 (B03) | 니트·옷깃·캔커피·은행잎·높은 하늘 | — |

블라인드 3라운드 판별자가 짚은 "복선 회수가 지나치게 정밀", "장식처럼 고르게 배치"도 같은 뿌리다. 그래서 v6은 **더하는 퇴고를 금지한다.**

## 순서

### 0. (논픽션만) 실화 카드
블로그·에세이는 사실이 있어야 사람 글이다. 작품(블로그) 시작 때 한 번 `runtime/LIFE_CARD_TEMPLATE.md`를 채운다. 본문에 들어가는 생활 디테일(사람, 장소, 습관, 물건)은 **카드나 사용자가 준 말에서만** 가져온다. 없는 사실은 지어내지 않고 `[실제로: 여기에 진짜 일]` 자리표시를 남긴다. 그럴듯한 평균을 지어내는 순간 글이 '누구나 쓸 수 있는 글'이 된다.

### 1. 말 초고 (raw)
- 휴대폰 녹음기에 대고 말하듯 **한 번에, 멈추지 않고, 다시 읽지 않고** 쓴다. 목표 분량의 1.5~2배.
- 생각나는 순서대로. 옆길로 새도 된다. 같은 단어를 반복해도 된다. '아니', '근데', '암튼'이 들어가도 된다.
- 금지: 제목, 소제목, 마무리 문장, 교훈, 비유를 짜내기, 앞에서 깐 것을 뒤에서 다시 쓰기.
- 파일로 남긴다: `초고.md`. 퇴고의 재료이자 증거다.

### 2. 빼기 퇴고 (final)
할 수 있는 것은 넷뿐이다.
1. **지우기** — 문장, 문단, 군말.
2. **순서 바꾸기** — 문단 단위.
3. **조사·어미 손질** — 문법이 틀린 곳만(갔다→갔음 같은 말투 통일 포함).
4. **오타·띄어쓰기.**

하지 않는 것: 새 문장, 새 농담, 새 비유, 마무리 한 줄, 교훈, '결국/마치/문득/비로소' 같은 다듬는 말, 앞뒤를 묶는 문장.
빼는 기준: 초고에서 **설계 티가 나는 문장부터** 지운다(교훈·요약·펀치 반복). 옆길 하나는 남긴다. 끝이 밋밋하면 밋밋한 채로 둔다. 상관없는 마지막 한 줄은 사람 글의 표시다.

검사:
```
python tools/subtract_check.py 초고.md 완성.md     # 더한 말 8% 이하, 덧칠 단어 0
python tools/voicecheck.py 완성.md --blog          # 블로그·에세이 (BL 원고는 --blog 없이)
```
`[더함]`이 뜨면 그 말을 지우고 초고에 있던 말로 되돌린다. 초고에 없는 말이 꼭 필요하면 그건 퇴고가 아니라 초고를 다시 쏟아야 한다는 뜻이다.

### 3. 제목 (블로그)
- 앞부분: 검색 키워드(예: `매일 글쓰기 1일차`). 모바일에서 30~35자 안에 키워드와 웃긴 부분이 다 보이게.
- 뒷부분: **초고 속에 있던 말**로만 만든다. 카피를 새로 짓지 않는다. `제목:` 줄을 완성본 첫 줄에 두면 `subtract_check`가 초고에 없던 말을 `[제목]`으로 보여 준다(키워드는 예외).
- 제일 이상하고 구체적인 한 장면을 고른다. '가을 감성' 같은 분위기 말보다 '갈비찜 네 번'이 이긴다.

### 4. 키워드 (블로그)
- 제목 앞부분 1회 + 본문에서 원래 하던 말 속에 1회(예: "10월 글쓰기 챌린지 목록") + 맨 아래 해시태그.
- "~를 검색하면" 같은 문장은 쓰지 않는다(B02). 검색어를 넣으려고 만든 문장은 독자가 먼저 알아챈다.

## 설계 금지 6 (손으로 확인)

1. 내 얘기를 세상 이치로 정리하지 않는다(S07).
2. 앞에 깐 것을 끝에서 묶어 보여 주지 않는다(S08).
3. 두 문단을 대구로 맞추지 않는다. 각각 쓰라는 글감이어도 길이와 소재를 다르게(S09).
4. 문단마다 한 줄 펀치로 끝내지 않는다. 웃긴 문단과 그냥 정보 문단이 섞여야 한다.
5. 소제목을 재치 있게 짓지 않는다('X 대신 Y'). 그냥 '1일차 글감'.
6. 모든 걸 회수하지 않는다. 안 풀린 것 하나, 상관없는 것 하나를 남긴다.

## BL 원고에 쓸 때

장면 카드와 손버릇 카드는 그대로 쓴다. 다만 후보 3개를 '잘 쓴 문장'으로 쓰지 말고, 각 후보를 **장면을 말로 쏟은 초고**로 만든 뒤 빼기 퇴고한다. `voicecheck`의 P_HUMAN·[판별] 항목은 빼기 퇴고 안에서만 맞춘다(지워서 맞추고, 더해서 맞추지 않는다).
